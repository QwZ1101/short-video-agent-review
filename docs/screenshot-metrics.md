# 抖音截图数据导入

若人工发现已确认的截图属于另一条作品，可通过 `ScreenshotStore.invalidate` 追加归属纠错记录，并用作品材料保存接口清空错误绑定。原始 `record.json`、图片和历史运行不改写。`invalidation.json` 绑定原记录指纹，后续复盘和比较拒绝使用该条记录；页面显示“归属确认有误”，旧结果也不再自动作为当前有效复盘复用。正确作品需重新导入并核对，不能直接把旧确认改成另一作品。

打开工作台的“截图数据”（`/metrics`），选择 PNG/JPEG 原图（最大 10MB）。

1. 上传原图：仅存本机，不调用模型。
2. 点击识别：复用配置的 DashScope 图片模型，一张记录最多尝试一次，失败不自动重试。浏览器轮询读取进度，刷新或重复点击不会重新调用。页面关闭后，只要服务仍运行，识别继续；服务退出会中断识别，可手工核对填写或另建记录。
3. 对照原图核对八项卡片指标：播放、点赞、评论、分享、收藏、弹幕、完播率和 2 秒跳出率。缺失项保留空值；0 是实际显示为零。万/亿展示值换算并注明精度限制。
4. 填写作品名称、截图对应的完整日期时间（北京时间）和统计范围，按需关联已登记视频。图表的新增/累计选项不自动用于判定卡片范围。范围不明可以保留“不确定”；指定时段需在备注写起止时间。
5. 勾选已核对后确认，生成不可覆盖的快照。要记录另一时点或更正已确认记录，请重新导入并注明原因。

识别结果不是人工确认。截图内容作为不可信数据交给模型，不执行其中任何指令。流量激励、曲线坐标和手机状态栏数字不能代替指标。无法从普通评论总数计算索要链接人数，也不能依据单张截图断言修改导致互动提升。

开始复盘页已包含截图上传、识别与核对区。确认保存后，选择该截图并核对它属于当前视频，再预览计划；“计算平台数据”会执行，原图进入证据目录。已有未关联视频的确认记录可明确选入本轮，关联其他视频的记录不能选入。历史工作流和人工复核结论不改写。原有人工 JSON 指标计算继续使用原来的同观察窗口规则。

工作流以 schema_version=2 冻结截图指标、记录编号、原图 SHA-256、确认时间、统计时间与范围；生成计划、启动和执行前校验截图和确认记录指纹。统计范围明确且有播放量时计算每百次播放点赞、评论、分享、收藏、弹幕数；未知范围仅汇总指标。完播率、2 秒跳出率保留为平台显示值，不反推人数。未知字段不补零，不编造发布时间、观察小时数或索要链接人数。单次统计不支持因果归因。

截图预览显示实际像素尺寸，默认不放大小图，提供 100% / 200% 查看；低分辨率提醒不会改变上传原件或模型输入。

工作流接入测试覆盖：截图进入冻结计划及模型证据、未确认与跨视频拒绝、计划后数据或原图变化阻止启动、未知范围不算比值、缺失与零的区分。请求与启动日志继续保存在 `reports/review-server/`、`reports/web-jobs/`；截图日志在 `reports/metrics-imports/`。

## 数据与日志

`reports/metrics-imports/metric-.../` 保存原图、SHA256、创建与识别时间、调用次数、识别模型和用量、机器候选、人工原始填写及规范化数值。每条记录含 `events.jsonl`（追踪编号、操作、时间、耗时、失败摘要）和一次性启动标记。模型原文最多保留 64000 字符并脱敏；日志不记录凭据。记录只在本机保存，Git 忽略；目录不自动清理。

HTTP 上传入口单独允许 15MB JSON（适配 Base64 开销），其他入口继续使用原有 300KB 限制。使用原有 loopback Host/Origin/令牌校验。上传检查大小和 PNG/JPEG 文件签名，不代表已验证图像全部像素；文件损坏时可在图像显示或识别阶段失败。

单个服务进程同一时间最多识别一张图，每个记录通过独占文件保证一次启动。不要同时启动多个服务对同一目录操作。浏览器没有自动保存人工核对中的改动，离开页面会提醒；原图与机器候选始终保存在本机。

## 验证

`python -X utf8 -m unittest discover -s tests -q` 覆盖单位与范围、未知值、原图指纹、确认冻结、单次调用、失败留档及 HTTP 访问保护。`node --check review-ui/dist/metrics.js` 检查脚本语法。
