# 智能编排的实现与验收

网页新任务默认启用智能编排。在高级设置中可关闭，旧请求未提供该字段时保持原行为。登记和预览不调用模型；启动后先执行规划，再执行通过校验的任务图。默认上限为 5 次：规划 1 次、分析与验证 2 次、故障恢复最多 2 次。每轮语义返修另需 2 次，规划本身不自动重试。

## 模型决策与实际执行

`workflow_planner` 是独立规划角色，提示词在 `prompts/workflow_plan.md`，随模板和其他角色提示词一起记录指纹。模型接收目标、受众、字幕与数据是否存在、配套材料数量，以及注册工具任务清单，不接收文件路径、图片或密钥。

模型可以选择：

- 分析重点：开头吸引力、行动引导、讲解清晰度或综合检查；程序把对应受控检查指引传给分析角色。
- 视频采样间隔：2、4 或 6 秒，通过 `prepare_video.py --interval` 实际执行，仍受既有图片覆盖和处理限制约束。
- 允许范围内的并行度、任务优先级和附加依赖；实际交由依赖调度器派发。

模型不能新增工具、代码或预算，不能删除必要阶段或证据依赖，不能在有数据时跳过数据计算，也不能将缺失数据变为存在。无效 JSON、错误样本 ID、越权工具、循环依赖或不完整回答都会在工具启动前停止，保留原始回答，不静默退回规则执行。模型规划不代表规划必然优于规则基线。

## 运行记录

每轮 `planning/` 保存 `input.json`、`prompt.md`、`model-output.txt`、`run.json` 和通过校验后的 `validated-plan.json`。网络失败时不存在原始回答文件，状态记录具体传输阶段和异常类型。总次数在调用前预留，失败尝试也计入；规划成功记录 `intelligent_plan_accepted`，实际派发记录 `scheduler_decision`。网页的“运行详情”显示本轮策略和理由。

命令行示例：

```powershell
python run_workflow.py --mode live --sample data/samples/<真实样本>.json --intelligent-planning --max-model-calls 3
```

这里 3 次预算不包含故障重试或语义返修；网页仍按选项计算总预算。
