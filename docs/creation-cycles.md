# 从视频 A 到下一条视频 B

## 统一工作区

### 作品材料与发布时间

登记页将视频、字幕、目标和数据截图放在同一个“作品材料”区。添加截图前会先保存视频资料并确定作品编号；核对截图后自动绑定到该作品，底部“保存作品材料”也可显式保存或暂不提供截图。再次打开会恢复绑定，预览计划会保存当前材料选择；模型启动仍需单独点击。

绑定记录与修订、操作日志保存在 `reports/work-materials/<sample_id>/`，不改写已生成的复盘快照。后续计划将截图选择冻结，之后更换作品绑定不会改变已生成计划。截图归属冲突、未确认记录或已变动的原图会被拒绝。

截图核对页自动解析识别结果的 `published_text`，仅接受完整年月日和时分，不推断缺失年份或相对日期。核对后保存为独立的 `published_at`，不能晚于截图统计时间；选入比较时自动带入。原图未能识别完整时间时留空，允许补充。历史确认记录缺少该字段时不追写。

首页和 `/cycles` 现在共用四步工作区：复盘 A → 选 1～2 条 → 应用并复盘 B → 比较与总结。每次只展示当前步骤；建议勾选后才展开编辑，比较设置默认折叠。登记视频、截图核对与人工复核在同源内页完成，返回时刷新来源和截图；已登记视频及已有复核可以复用。运行模型仍须明确点击启动。

视频 B 有可用的已提交人工复核后，工作区才开放新的比较与总结；历史比较仍可查看。首次绑定 B 仍需说明实际采用情况，真实发布时间和不明确的截图口径仍需人工核对，系统不推测。

“结束本轮，重新开始”将未完成计划标为 `closed` 并写入历史及事件日志。已总结计划直接开始新循环。历史不删除；浏览器记住最近打开的计划，`?fresh=1` 可打开空白新循环。

在人工复核提交后打开“改进与下一条”，选择“制定下一条计划”。独立入口是 `/cycles`。原有本视频修改记录继续保留，不会迁移或自动改成跨视频结论。

已提交复核中，即使其他条目仍“暂不确定”，明确选择“保留候选稿／修改后采用”的建议也可进入计划。草稿和不确定项不可选；部分认可时，复核页面直接显示计划入口。提交后的来源复核如再次改变，需要重新建立计划，避免沿用旧判断。

1. 从 A 的已提交复核明确选 1～2 条，分别写下一条的具体动作；登记 B 题材、主指标、期望方向、发布后观察小时数和时间容差。保存后本轮计划冻结。
2. 先按清单创作 B，然后在 `/start` 登记 B。回到计划关联 B，逐条填写已采用、部分采用或未采用，以及实际做法、视频时间位置或版本。实际采用不等于效果有效。
3. 上传并人工确认 A、B 各自的数据截图。在计划中选截图，填写两条视频的发布时间、核对作品归属和目标定义，说明题材、时长、流量来源等其他差异。
   返回计划页面时会自动刷新已确认截图列表；第 03 步也提供“刷新已核对截图”按钮。刷新保留已选截图和其他填写内容，仅列出对应视频或未绑定视频的已确认记录。
4. 程序用“截图统计时间 − 发布时间”计算实际观察时长。两边须在预登记窗口的容差内，二者时长差也不得超过容差；仅接受已确认的发布后累计口径。程序不修改截图时间来凑窗口。
5. 对齐后给出原值、绝对变化和相对变化；平台百分比的绝对差以百分点表示。零分母或缺失主指标不计算，未知不补零。含万／亿的值标注近似。
6. 逐条决定继续保留、再试一条、暂不采用或暂不能判断，并写下一条行动。不同视频的比较不属于随机 A/B 实验，不自动判定有效或写入旧任务的验证通过状态。
7. 复盘 B 并完成人工复核后，由本轮总结入口“从 B 开启下一轮”，保留父计划关联。新一轮只能使用上一轮 B 的已提交复核。

## 没有同观察窗口的数据

A 已发布很久、却没有当时的截图时，当前累计值无法还原发布后 24 小时的数据。可记录“缺数据，暂不比较”，写明缺什么以及下次怎样采集。此时总结只允许“暂不能判断”，本轮可作为后续观察的基线。补齐数据前不制造差值或结论。

B 在计划登记前已发布时，比较结果标为回顾性，不冒充预先设计的试验。题材、时长、受众、发布时间、配乐、流量激励或投流等可能同时变化；多项改动一起采用也不能分离贡献。本版不做统计显著性检验，不自动计数索要链接人数。

## 数据与日志

- `reports/creation-cycles/cycle-.../record.json`：本轮当前记录；`history/revision-...json`：不可覆盖的历次版本；`events.jsonl`：时间、计划 ID、操作、版本与状态。
- 来源人工复核、截图 SHA-256、确认记录 SHA-256 和本轮采用情况均可追溯。来源复核或历史文件变化会阻止沿用；比较后截图或确认记录变化会阻止总结。
- 修改 B 或实际采用情况会清空当前对比与决定，旧值留在历史。总结后冻结，本版更正通过新建计划并说明原因处理。
- HTTP 操作复用本机 Host/Origin/令牌校验，日志不记录正文和凭据。周期页面与比较计算不调用模型；视频复盘和截图识别仍遵守原预算入口。
- 文件均在被 Git 忽略的 `reports/` 中，源码提交不包含用户截图、运行记录或 API 密钥。

## 验证范围

新增测试覆盖少量选择、来源冻结、实际采用与效果分离、时长及口径拦截、零与缺失值、百分点与相对变化、缺基线结案、父子计划归属、修订失效、来源篡改和 HTTP 访问校验。合成数据和浏览器验收不代表真实视频已产生效果提升。
