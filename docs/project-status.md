## 已实现

- 截图数据入口：开始复盘页内上传原图、单次 DashScope 识别八项指标，人工确认后选入本轮平台数据计算。指标、原图和确认记录指纹随计划冻结；未确认及跨视频数据不可直接使用。
- 下一条改进循环：从已提交复核选择 1～2 条、冻结创作计划与观察窗口、关联视频 B 并记录实际采用、核对累计截图的实际观察时长、比较并逐条决定下一步。缺少可比数据可记为暂不能判断，父子计划可追溯；属于观察性比较，不自动宣称因果效果。

- 本地样本登记、材料检查、抽帧和字幕关联。
- 分析与验证两个独立模型调用，结构、引用及图片指纹检查，调用预算与失败留档。
- 人工复核、修改任务、作品版本和人工验证记录。
- 规则生成任务计划，明确角色、工具、依赖、输入输出和条件分支。
- 同一观察窗口的平台数据手工录入格式及本地计算；未提供时明确跳过，错误格式在模型调用前拒绝。
- 日志页面显示任务计划、阶段状态、耗时、失败原因与请求追踪；本地 Git 与私有 GitHub 备份。
- 一次性格式修复入口，保留原失败记录；不是语义自动返修。
- 可选的语义返修与独立再次验证，最多两轮并受总调用预算限制；证据不足时停止等待补证。已有流程可创建一次独立继续记录，不允许串联追加预算。
- 历史成功案例的同证据成对评估包、人工标注草稿与冻结提交、支持比例和覆盖率、历史耗时与用量计算。未确认草稿不计分；回顾性开发案例不冒充独立测试集。
- 网页基础样本登记、材料与环境预检、2 / 4 / 6 次预算预览、后台单次启动及阶段进度；重复请求不重跑，失败记录可回看。

## 当前边界

规则调度并不等于模型自主规划；两次模型意见一致不代表事实正确。程序测试通过不等于真实视频建议可靠，也不等于互动提升。数据计算是工具能力，尚未有实际平台数据对比结论。
