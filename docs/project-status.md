# 项目进度与剩余验收

更新日期：2026-10-27。本文列出开发与演示验收，不替代比赛通知的正式提交要求。

## 当前目标

观众看完粒子效果与制作过程视频后索要展示网页链接，或点赞，任一即可。旧目标的下载、安装及本地运行任务仅作为历史记录，不再列入当前待办。

## 已实现

- 本地样本登记、材料检查、抽帧和字幕关联。
- 分析与验证两个独立模型调用，结构、引用及图片指纹检查，调用预算与失败留档。
- 人工复核、修改任务、作品版本和人工验证记录。
- 规则生成任务计划，明确角色、工具、依赖、输入输出和条件分支。
- 同一观察窗口的平台数据手工录入格式及本地计算；未提供时明确跳过，错误格式在模型调用前拒绝。
- 日志页面显示任务计划、阶段状态、耗时、失败原因与请求追踪；本地 Git 与私有 GitHub 备份。
- 一次性格式修复入口，保留原失败记录；不是语义自动返修。

## 剩余工作（按优先级）

| 优先级 | 工作 | 验收条件 |
| --- | --- | --- |
| P0 | 验证反馈驱动的受控返修 | 区分“需修正”和“证据不足”；前者生成明确修正任务，后者停等补证；设置总预算和轮数，保留每轮输入输出，不能无限重试或自动宣布事实正确 |
| P0 | 新目标下的真实案例 | 至少两条视频按当前目标完成分析、验证和人工复核；实际采用的建议形成可追踪修改版本，不能把旧目标任务当作当前结果 |
| P1 | 统一运行入口 | 网页完成样本登记、查看计划、启动任务及进度显示；防止重复启动；运行前显示模型阶段预算 |
| P1 | 人工标注与对照评测 | 冻结标注后再运行；单模型和分析+验证使用相同证据，计算人工确认比例、引用准确性、完成率、耗时与用量；测试集与调参案例分开 |
| P1 | 实际创作效果记录 | 手工补录同口径播放、点赞、索要链接及观察窗口；没有数据时保持未知；不把相关变化写成因果证明 |
| P1 | 可复用工作流模板 | 把角色、依赖、工具白名单和预算从代码整理成有校验的模板；至少展示一个可复用场景及条件分支，不能仅替换视频标题 |
| P2 | 交付与演示 | 在不含私人材料的新目录验证启动与测试；准备架构、失败恢复与条件分支演示、安装说明、演示脚本，并逐条核对正式参赛要求 |

## 当前边界

规则调度并不等于模型自主规划；两次模型意见一致不代表事实正确。程序测试通过不等于真实视频建议可靠，也不等于互动提升。数据计算是工具能力，尚未有实际平台数据对比结论。

下一开发里程碑：完成受预算约束的语义返修与补证停止路径，再建立同输入对照评测。网页启动入口随后接入已经验证的流程。
